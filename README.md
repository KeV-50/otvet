1) Да, она сможет прочитать notes.txt, если знает точное имя файла и может «дойти» до него по пути (то есть у неё есть право x на всех папках по дороге). А вот ls не покажет список файлов — для этого нужно право r на саму папку. Простыми словами: r на папке — это «увидеть, что внутри», а x на папке — это «пройти через неё», но не подсмотреть содержимое.

2) Копия будет в группе Alice, потому что cp создаёт файл заново в новом месте. Бит setgid висел на той папке, где лежал оригинал — он сработал, когда оригинал только создавался, поэтому файл и попал в группу developers. А копия создаётся уже в домашней папке, где такого бита нет, — значит, группа берётся обычная, от создателя.

3) Это две разные вещи, которые работают по-разному. nologin просто не даёт зайти в систему руками (например, через консоль) — это как заклеить дверь. sudo устроен иначе, и если им пользоваться неправильно, можно потерять весь сервер. Почему nologin + одно правило sudo надёжнее, чем просто sudo? Потому что в первом случае человеку разрешена ровно одна команда, а во втором — вообще всё, что может root.

4) Для самого webapp ничего не меняется: и с 700, и с 777 у владельца всё те же полные права rwx — первая тройка цифр одинаковая. Разница только в том, что 777 раздаёт права ещё и всем остальным.
